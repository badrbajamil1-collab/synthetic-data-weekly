The code, honestly

read line by line

Holds up

  • One failure can’t sink the run. Each collector is wrapped in try/except, partial feed failures become warnings, and collect_all always returns items + errors + counts.
  • Dates are re-checked, not trusted. Google’s when:7d is treated as a hint; _in_window filters post-parse and rejects future dates.
  • Rule #1 is structural. report_build.py verifies all links and removes dead ones before rendering — a broken link can’t reach the report even by accident.
  • Real-world traps handled. HN returns 419 to bots, so it’s verified through the Algolia API; Reddit gets one multi-sub request and four backoffs; Google News redirects are resolved via the batchexecute RPC.
  • Verification reads the artefacts, not memory. verify_report.py re-parses the emitted Markdown/HTML — 20/20 checks pass, including “link set is exact”.

Doesn’t hold up

  • Nothing is versioned. Zero commits, README.md is 0 bytes, no requirements.txt, no .env.example. The project cannot be rebuilt from the repo.
  • memory.py is dead code. Nothing calls it, history.db is never created — so “no link in two weeks” is unenforced. Next Saturday can resend today’s eight picks.
  • normalize_url is never called. Dedupe compares raw strings, so ?utm_source=… variants survive as distinct items.
  • categories in config is a lie. The arXiv key at config.yaml:31 is read by nobody; the collector searches all:“synthetic data”, so a cs.LG paper that never says the phrase is invisible.
  • No pagination anywhere. GitHub gets 15 results per query × 4; arXiv 25 per query. Coverage is capped by config, not by what exists.
  • Two metrics are fake. items_found and items_after_dedupe both read len(raw); source_errors reads raw_run_log.json, which no collector writes — it is always [].
  • AgentState is the wrong shape. A Pydantic model can’t be a LangGraph state; Phase 4 needs a reducer-typed state or every node silently overwrites the last.
