# AGENTS.md — Weekly Synthetic Data Research Agent

Python 3.13 / uv, Windows + PowerShell 5.1. Collects 7 days of synthetic-data
content, renders a weekly report, and emails it. The **collect → clean → rank →
fetch → report → render → send** chain runs as a LangGraph state machine
(`src/synthetic_data/graph.py`). Deliverables live in `progress/`;
`progress/README.md` is the index of what has been produced.

`main.py` prints **every** item by default — that is the Phase 1 deliverable, "a script
that prints all raw items found this week". `--limit N` caps the print; `--all` is the
same as `--limit 0`. Items already recorded in `history.db` are excluded from the print
and counted in the summary as `already sent (history)`.

`--source` takes collector names (`arxiv`, `news`, `blog`, `reddit`, `hn`, `github`),
not the `config.yaml` keys.

`python` is not on PATH on this machine — use `.venv\Scripts\python.exe` or `uv run python`.
There is no pytest, linter, formatter, typecheck or CI. `selftest.py` + `verify_report.py`
are the test suite; both exit non-zero on failure.

## Pipeline

`main.py` → `cli.main` → `runner.collect_all` → the 6 collectors in `collectors.py`.

- **Collect-only** (Phase 1): `python main.py` → `raw_items.json` + `raw_run_log.json`.
- **Full weekly pipeline** (Phases 4–5): `python main.py --pipeline` →
  `synthetic_data.graph.weekly_run` → LangGraph
  `collect -> clean -> rank -> fetch -> report -> render -> send`.
  `--dry-run` writes `email.eml` instead of sending; `--no-email` stops after render.

`report_build.py` verifies every link, drops dead ones, then writes
`report.md`, `report.html`, the PDF and `run_log.json` into `progress/week-<week_end>/`.
`verify_report.py` defaults to the newest `progress/week-*/source.yaml`. The old
top-level `reports/` directory no longer exists.

`send_report.py` → `synthetic_data/emailer.py` builds a multipart message: `report.md`
as `text/plain`, `report.html` as the `text/html` body, and the week's PDF attached.
Recipients come from `config.yaml`; SMTP credentials come from `.env`. A standalone
send records the report's URLs in `history.db` (`--no-record` opts out). `--dry-run`
writes `progress/week-<date>/email.eml` and touches neither SMTP nor history;
`--test` sends only to `DRY_RUN_RECIPIENT` and also records no history.

### Phase 4 — the graph

`src/synthetic_data/graph.py` builds the `StateGraph` over `AgentState` (a `TypedDict`,
not a Pydantic model — LangGraph requires TypedDict). Nodes:

- `collect` → `clean` → `rank` → `fetch` → `report` → `render` → `send` → `END`.

`collect` applies `history.db` before ranking, writes `raw_items.json` and
`raw_run_log.json` (the same artefacts as the Phase 1 CLI), and carries the
`already_sent` count into the run log.

`fetch` calls `fetch_candidates.fetch` for the ten best in-window items, so summaries
are written from the real abstract or page text rather than the ranking snippet. A page
that cannot be fetched keeps its snippet, and the report discloses that. `render` fills
`report_markdown` / `report_html` in state from the files `report_build.py` wrote (the
dead-link filter has already been applied), ready for the email body.

`render` calls `report_build.py` with `--no-record`. `send` is the only node that marks
URLs in `history.db`, and only after SMTP succeeds. A dry run, a `--no-email` run and a
failed send therefore leave history untouched, so the next run can still offer the
same links.

The 7-day window applies to **every** section: `summarise.compose_sections` takes top
picks, tools and worth-a-look from the same eligible list, so an older release cannot
re-enter through a side section. `verify_report.py` checks dates in all three sections.

Nodes never raise out of the graph; they record the error in state and return, so one
failing source or one failing model call does not stop the report. Run it:

```
uv run python main.py --pipeline
```

The collect-only behaviour of `python main.py` is untouched and stays reproducible.

### Phase 2 — ranking

`rank_items.py` → `synthetic_data/rank.py` for logic, `synthetic_data/llm.py` for
the only HTTP call to a model. Output is `ranked.json`; `score_cache.json` makes a
rerun free and byte-identical.

Three rules that are easy to break:

- **`llm.py` owns transport retries; `rank.py` never retries a batch.** A batch with
  missing rows falls back to one call per item. Two retry layers would multiply into
  8+ calls per batch.
- **Rows are plain dicts**, not `Item`. Pydantic's default `extra="ignore"` would
  silently drop `well7_fit`, `score_status`, `duplicate_of` and `scored_by`.
- **Cache before duplicate grouping.** A demoted duplicate score must never be
  stored, or every rerun subtracts the penalty again.

## Gotchas that will bite

- **Hacker News returns HTTP 419** to non-browser clients. That is not a dead link;
  `links._check_hacker_news` verifies through the Algolia API deliberately. Do not
  "fix" it into a plain status check.
- **Google News RSS links are opaque redirects** (`news.google.com/rss/articles/...`)
  that return 200 for anyone. A 200 proves nothing until `links.resolve_google_news`
  unwraps them via Google's `batchexecute` RPC.
- **Reddit:** use `.rss` with no trailing slash — `/.rss` returns 429. Roughly 1 request
  per minute per IP, so the collector backs off 15/30/45 s. A second full run inside a
  minute stalls ~90 s; that is rate limiting, not a hang.
- **arXiv announces nothing Friday or Saturday**, so most weeks end with a date gap.
  Expected. Its `all:` search also matches loosely — expect off-topic papers in the raw list.
- **GitHub search filters on creation and push dates**, not publication date, and
  returns repos that merely mention the query. Repos created inside the week are
  news on their own; older ones count only when a release shipped that week.
  Treat the ranking as noise.
- **PowerShell 5.1**: no `head`, `wc`, `sed`, or `&&`. Use `Select-Object -First`,
  `Measure-Object`, `;`.

## Wiring that is easy to mistake for dead code

- `links.normalize_url` **is** called — `runner.dedupe_items` keys on it, and so does
  `memory._key`, so dedupe and history agree on what "the same URL" means.
- `memory.py` is wired both ways: `collect_all` filters against `history.db` when it
  exists (never creating it), and a successful send (standalone `report_build.py` or the
  graph's `send` node) marks the published URLs. The graph's `render` node passes
  `--no-record` deliberately. Deleting `history.db` replays a week from scratch.
- `raw_run_log.json` **is** written by `cli.main` and by the graph's `collect` node, and
  `report_build.py` reads it for `items_found`, `duplicates_removed`, `already_sent` and
  `source_errors`.
- `config.yaml` → `sources.arxiv.categories` no longer exists; a comment records why.
- `schedule` **is** read now — by `schedule_task.py`, which registers the Saturday task.
- `recipients` **is** read now — by `emailer.deliver`.
- `report_build.py` exits **1 when it dropped dead links** — that is a successful render of
  a filtered report, not a crash.

## Phase 2 behaviour that looks like a bug

- **A long tail of 1s is correct.** On the 2026-11-04 week, 152 of 222 items scored
  1–2 and spot-checking confirms they are noise: a Fashion-MNIST tutorial, LLM
  inference benchmarks, 3D Gaussian splatting, a conference-reviewing thread. Phase 1
  says out loud that arXiv `all:` matches loosely and GitHub returns repos that merely
  mention the query; that is what the tail is. Do not "fix" the prompt to spread the
  scores out.
- **The top 10 used to over-represent GitHub.** The rubric rewarded "new tools", so a
  repo whose description read "federated differentially private tabular synthesis"
  scored 10/10 whether it had 447 stars or 0. Tuned on 2026-11-06: the collector now
  puts stars and project-creation date into the snippet (never the title), the rubric
  tells the ranker to discount repos older than three weeks with under 10 stars, and
  both shortlist paths cap GitHub's share (`ranking.github_share_cap: 3`). The
  `(stars: 0)` title suffix that polluted duplicate grouping is gone. `RUBRIC_VERSION`
  was bumped, so the next run re-scores everything. Judged properly in Phase 6, on a
  real week.
- **`ranked.json` rows are dicts, not `Item`.** See the Phase 2 section above.

## The report format is contractual

`report.md`, `report.html` and the PDF are checked by `verify_report.py` against the brief:
subject prefix, section order, footer text, 5–10 picks, tool counts, no duplicate links,
top-pick dates inside the week, PDF over 40 KB. Do not restyle prose to taste — edit the YAML in
`progress/week-<date>/source.yaml` and re-render.

The PDF is the single intentional deviation: glossary first, then the report. Email and
Markdown follow the spec order exactly.
